# Project 1.2 — Selective ML Clinical Review for Naloxone at Discharge

A privacy-safe selective-prediction system that estimates **post-discharge opioid-related adverse-event risk** and uses that estimate to prioritize encounters for human naloxone-at-discharge review. It is deliberately **not** an autonomous prescribing system and does **not** learn to imitate existing naloxone prescribing behavior.

## Problem formulation

The prediction target is a downstream 30-day adverse event generated from a semi-synthetic longitudinal data-generating process. Existing naloxone prescribing is generated separately, excluded from model features, and used only in explicit review-eligibility logic. This separates prediction of downstream risk from reproduction of existing clinician or site prescribing behavior.

The system evaluates four questions:

1. Can a discharge-time model identify patients at higher post-discharge opioid-related risk?
2. Does a nonlinear model add useful signal beyond a transparent rule and logistic baseline?
3. At a fixed human-review capacity, what validation-selected threshold is appropriate?
4. Where should the system **defer** rather than rank automatically because of data quality, missing critical inputs, model disagreement, or near-threshold uncertainty?

## System flow

```text
privacy-safe longitudinal encounters
        ↓
feature registry + leakage audit
        ↓
temporal train / validation / test split
        ↓
transparent clinical-rule comparator
        ↓
logistic regression + nonlinear model
        ↓
validation-set model selection
        ↓
validation-set capacity threshold
        ↓
test-set calibration/discrimination/error/subgroup evaluation
        ↓
eligibility logic + selective deferral
        ↓
PRIORITY_REVIEW / DEFERRED_DIRECT_REVIEW / NOT_ELIGIBLE
```

## System capabilities

- 8,000 privacy-safe semi-synthetic encounters spanning 2023–2026
- Known post-discharge event data-generating process with clinically structured risk factors and nonlinear interactions
- Explicit feature registry documenting timing, model inclusion, and leakage risk
- Strict discharge-time leakage audit
- Temporal split: train through 2024, validation during 2025, test during 2026
- Transparent rule-based comparator
- Logistic regression baseline
- HistGradientBoosting nonlinear model
- Validation-only model selection
- AUROC, average precision, Brier score, and 10-bin calibration error
- Validation-selected reviewer-capacity threshold
- Precision, recall, and review-fraction evaluation
- Capacity/utility analysis
- False-positive and false-negative review artifacts
- Subgroup evaluation by sex, site, procedure group, and OUD history
- Logistic coefficient table and model-agnostic permutation importance
- Explicit naloxone review-eligibility logic
- Selective deferral for:
  - unresolved Project 1.1 data-quality flags
  - missing critical discharge-time inputs
  - large simple-vs-nonlinear model disagreement
  - estimates too close to the capacity threshold
- Human-readable case drivers presented as contextual risk signals rather than causal explanations
- Priority and deferred review queues
- Saved selected and alternate model artifacts
- Automated tests

## Human-in-the-loop review

The model does not determine whether naloxone should be prescribed. Human judgment remains necessary for target definition, discharge-time feature validity, review eligibility, review capacity, false-positive and false-negative costs, subgroup performance, and resolution of deferred cases.

Upstream data-quality uncertainty from Project 1.1 is propagated into Project 1.2 rather than silently imputed away.

## Run locally

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
pytest -q
python run_pipeline.py
```

An editable package install is optional if you want the command-line entry point:

```bash
python -m pip install -e .
p2-review
```

The pipeline generates the synthetic dataset if needed and overwrites derived outputs deterministically using the configured random seed.

## Design rationale

- **Why not predict naloxone prescribing?** Existing prescribing reflects clinician and site behavior. Predicting a downstream adverse event instead separates risk estimation from imitation of current practice.
- **Why use a temporal split?** It more closely approximates prospective use and reduces the risk that random splitting obscures temporal drift.
- **Why retain logistic regression?** It provides a transparent reference model. A nonlinear model is selected only if it demonstrates added value on validation data.
- **Why choose the threshold on validation rather than test data?** The test set is reserved for final evaluation; reviewer capacity is fixed before test-set performance is assessed.
- **Why defer cases?** Data-quality problems, missing inputs, model disagreement, and near-threshold estimates represent uncertainty that should not be hidden by automatic ranking.
- **Why use simple case drivers rather than SHAP?** The displayed drivers are transparent prespecified risk signals and are not presented as causal explanations or model-specific attribution values.

## Limitations

This is a research prototype using synthetic and semi-synthetic data. It is not validated for patient care, is not a clinical guideline, does not establish clinical effectiveness, and must not be used to make real prescribing decisions.

Project 1.3 addresses a separate causal question: whether an intervention changes downstream outcomes.
